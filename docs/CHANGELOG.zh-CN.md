# 更新日志

[English](./CHANGELOG.md) · **简体中文**

本文件记录 Flikky 每个版本面向用户的变更，格式参照 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)。版本号遵循 `x.y.z`：x 重大架构变更、y 功能新增、z Bug 修复。日期为 tag 创建日期。

## [v1.21.0](https://github.com/Lifky/Flikky/releases/tag/v1.21.0) · 2026-09-19

三条新通道，一套权限模型。手机相册在两端均可浏览，已安装应用可提取 APK 并发送，连接卡片提供二维码，而对端到底能看到什么，现在由一个面板明确回答。

### 新增

#### 对端能看到什么
- 会话头部新增**对端权限面板**，把所有「浏览器能否看到」的开关收进一处。每条通道只呈现三种状态之一：不可用（手机缺权限）、关、开 —— 于是「开关开着但什么都没出现」不再是一条沉默的死路
- 头部在设备名旁**常驻显示当前开放了哪些通道**
- **通道锁就放在内容所在的地方**：文件与相册两个 tab 的左下角各有一个锁按钮，不离开当前界面就能对对端关闭该通道
- **收藏拆成两条独立的轴**：功能在 App 里是否存在，以及浏览器是否可见。关掉功能不再隐含「对端本来有权限」这层意思

#### 手机相册
- 会话页新增**相册 tab**：按拍摄日期分组的单条时间线，三列，点击预览、长按进入多选。**长按后拖动可连选一段**，回拖会撤销本次手势新增的项，按住时贴近屏幕边缘会自动滚动
- 浏览器新增**相册面板**：同一条时间线，缩略图**固定尺寸**并随面板宽度换行，每个格子有自己的选择角标（鼠标没有长按），多选下载复用文件面板的工具栏
- 两端都可**按相册文件夹浏览，而不只是按日期**：在时间线与相册簿封面网格之间切换，封面来自 MediaStore 的 bucket 名，点进去是该簿自己的时间线。时间线回答「最近拍的」，相册簿回答「微信存的那张在哪」
- 相册使用 **Android 的窄口径媒体权限**而非「所有文件访问」，并支持 Android 14+ 的「仅选定照片」—— App 会说明当前能看到多少项，并提供回到系统选择器扩大范围的入口

#### 发送已安装的应用
- 加号 sheet 新增**「应用」tab**：搜索已安装应用，选中后 Flikky 提取其 base APK 并发送进会话。发送的文件名为 `应用名_版本.apk`
- 含 **split APK 的应用只发送 base.apk，并给出明确警示** —— 拆分包无法从单个文件还原成可用的安装
- **APK 行提供安装操作** —— 文件总览、传输完成后的聊天气泡、历史记录三处都有 —— 由系统安装器接手
- 文件总览中 **APK 安装包成为独立的文件分组**，使用官方 `apk_document` 符号
- 应用列表**默认只列用户安装的应用，可切换为包含系统应用**；列表为空时提供进入系统权限设置的入口

#### 免输入地址
- 连接卡片在「复制地址」旁新增**二维码按钮**，点开是一个装着二维码的 bottom sheet。它**只编码 URL** —— 一次性 PIN 仍留在手机屏幕上由用户输入，因为可被扫走的凭据本身就是一条新的泄露路径

### 变更
- 两个对端门控从快捷设置移入权限面板；快捷设置只保留改变 App 自身外观的项
- 「发送已有文件」成为加号 sheet 的第二个 tab，不再是 tab 行上的独立动作，于是所有「把内容放进会话」的入口都从同一个按钮开始
- 会话头部的三个面板动作移到自己的一行。与设备名挤在同一行时，被截断的永远是设备名
- 文件与相册两个 tab 的锁 FAB 与选择 FAB 现在共用一份几何定义，只声明一次 —— 两个 tab 不可能再各自漂移
- **语言切换立即到达浏览器。** 浏览器原先每秒轮询一个一年只变几次的设置；现在跟随 App 自身的配置回调，仅在连接空闲时作为兜底轮询
- 相册缩略图只下载一次并跨虚拟行复用，带并发上限、请求去重与页内缓存，断开连接时清理
- App 主页与收藏的空状态共用同一套图文锚点，两页因此能对齐
- **服务器的地址校验从黑名单收紧为白名单。** 原先只排除几个已知不可用前缀、其余一律放行，那会让公网 IPv4 通过；现在只接受 RFC1918 私有段，并直接排除 VPN 与蜂窝 transport

### 修复

- **关闭对端通道现在会切断已在进行中的传输。** 门控原先每个请求只检查一次，于是用户关闭访问后，一个 2 GB 的下载仍会跑到完成 —— 而用户关它的动机通常恰恰就是「这个文件不该到对端去」。存储与相册两条流现在都在每个 64 KB 块之前重新读取门控
- **手机与浏览器对「照片拍摄于哪一天」的判断曾经不一致。** 两端各自用自己设备的时区从时间戳推算日期，于是手机与电脑处于不同时区时，接近午夜拍摄的照片在两端落进不同的分组 —— 分组数不同、标签不同，同一个相册看起来像两个。拍摄日期现在在手机上算一次，随每一项下发
- 相机时间设错而落在未来的照片会形成多个各自独立、却都标着「今天」的分组
- 浏览器相册的缩略图会随面板宽度缩放且永远一行三个；现在是固定尺寸并自动换行
- 浏览器相册滚动发涩、鼠标滚轮常常无效：虚拟窗口在每次滚动事件都整块重建，这既让已在屏幕上的缩略图重新发起请求，也与浏览器的滚动锚定相互打断。现在窗口只增删真正变化的那几行
- 加载失败的缩略图会在每次重绘时重试 —— 一个缺失的项能产生几百次请求。失败现在会被记住，直到用户显式刷新
- 在浏览器相册里拖动缩略图会触发会话页的「松开以发送文件」浮层，提示把手机自己的照片再发回手机
- 相册会列出并非可浏览照片的记录：仍在写入的文件、回收站中的项，以及零字节的行
- **切换 Wi-Fi 可能让服务处于「已绑定但连不上」的状态。** 绑定失败不再被记为成功，同一地址允许重试，热点变化在没有系统回调时也能被发现，迟到的回调不能复活已停止的服务
- 换到新 IP 后会换发一次性 PIN 并作废旧 Cookie，因为 Cookie 无法跨 host。同 IP 重绑保留原有登录
- 浏览器可能响应一个它已经替换掉的 socket 上的事件；重连原先也只追加新历史 —— 断线期间发生的文件完成、失败与撤回现在会被校准
- App 断开后浏览器的语言轮询仍在继续
- 在历史记录或会话页打开浮动操作栏可能陷入反复重绘

## [v1.20.0](https://github.com/Lifky/Flikky/releases/tag/v1.20.0) · 2026-09-13

到目前为止最大的一版，分三个阶段做完：手机自己的存储在两端都能浏览了；每一个文件界面都有了排序与搜索；缩略图与预览覆盖到存储列表和收藏面板；行首视觉（leading）全局可定制。

### 新增

#### 浏览手机存储
- **会话页新增「文件」tab**：浏览手机自己的存储，单击文件即勾选（跨目录累积），一次把整批发进会话。它与「会话」tab 并列，左右滑动切换
- **浏览器端新增「文件」面板**：远程浏览手机存储，通过可折叠的面包屑逐级进入目录，逐个下载或多选批量下载。不需要先在手机上发送
- 新增**「允许电脑浏览手机存储」开关，新安装默认关闭**。关闭时浏览器端完全不显示「文件」入口，服务端所有存储接口一律返回 `404`。列出文件需要 Android 的「所有文件访问」权限，而该权限没有只读版本——Flikky 只读取。详见 README 的安全模型章节
- 新增**「显示隐藏文件」**设置，默认关闭
- 服务端现在**在手机自己当热点时也能绑到正确地址**。这个场景从一开始就写在安全模型里，但一直没实现：没有已连接的 Wi-Fi 时应用取不到地址，服务起不来

#### 排序与搜索
- **六个界面都能排序**：主页、收藏页、文件总览页、手机上的文件 tab，以及浏览器端的文件面板与收藏面板。点一个新的排序键，用它自己的自然方向——名称升序、时间与大小降序；再点当前键则方向翻转。每个界面各记各的选择，手机与浏览器也各记各的
- 「时间」指什么逐处写明：主页是会话开始时间，收藏页是存进弹药库的时间，文件总览页是消息时间，存储文件是文件系统的修改时间
- **在当前目录内搜索**，两端都有：输入即过滤，不发新请求，文件夹也能被匹配到。换目录时关键词自动清空
- 主页的**分节方式**——不分节 / 按状态 / 按日期。三种模式此前都已写好却从未接上任何入口，也就是说一次都没有在真机上渲染过

#### 缩略图与预览
- 存储列表与收藏面板里的图片、视频现在**两端都显示缩略图**，由一层磁盘缓存供图；缓存键是「路径 + 修改时间 + 大小」，按上限做 LRU 淘汰
- 点缩略图**打开预览**：手机端图片走应用内查看器（支持捏合缩放）、视频交给系统播放器；浏览器端三个来源共用同一个全屏 lightbox。点行体仍然是勾选，语义完全没变
- 新增**缩略图缓存设置**：上限可选 0（不缓存）/ 50 / 100 / 200 MB，显示当前占用，并可一键清空。「删除全部数据」也会一并清掉
- SVG 刻意不生成缩略图、也不走 inline 渲染

#### 行首视觉可定制
- **行首容器的形状可选**，25 个官方 Material 3 Expressive 形状排成网格；凡是有行首容器的地方全部跟随：文件总览页、收藏页、两个快发 Sheet、文件 tab、聊天页文件气泡，以及浏览器端对应的三处
- **行首容器三档配色**：六种类型共用一个主题色（与此前一致）、与主题调和的分类色、固定分类色。每一档下面都有一条六色预览带，与六种文件类型实际显示的颜色一致
- **压缩包成为独立的文件分类**，用官方 `folder_zip` 图标——ZIP / RAR / 7z 不再被归进「其他」。分类筛选因此变成 7 个 chip，窄屏可横向滚动
- 两项选择都实时同步到浏览器、杀掉应用重开仍在、导出导入也带得走

### 变更
- 双端打开大文件夹改为渐进加载。服务端以 NDJSON 逐条 flush 地流式输出，两端边收边追加，不再等整个目录读完。每个条目的属性从 3 次调用合成 1 次，2000 项的目录从约 6000 次文件系统调用降到 2000 次
- 浏览器端文件列表只渲染视口附近的行。一个一万项的文件夹原本往页面里放 11 万个元素，现在只有几百个——内存占用与滚动卡顿都出自那里
- 手机端的列举不再占用主线程，路径与进度在点击的一瞬间就出现，新的导航会取消上一次
- 回退到逛过的文件夹**秒回**，并回到离开时的位置，手机与浏览器都是。刻意不做自动重读；两端各有一个刷新按钮作为手动出口
- 双端都会写明选择集里有多少项在其他文件夹——计数大于屏幕上的勾选不再是个谜
- 浏览器端全选与取消全选合并为面板头部的一个两态按钮，当前文件夹没有可选项时它隐藏。它在列表完整到达前保持不可用：条目还在陆续到达时，「全部」没有确定含义
- 双端文件列表末尾新增终止标记——加载中写「正在载入… 已 N 项」，完成后写「共 N 项」——于是「加载完了」与「只是停止生长了」终于可以分辨
- 文件夹的副标题两端统一显示项数，不再是手机上写「文件夹」、电脑上写「13 项」
- App 端选中后的操作条换成了 Material 3 的 FAB 菜单
- 会话页的 tab 栏只在浏览器已连接时出现——文件 tab 里能做的事全都需要连接
- 文件行逐行淡入（阶梯封顶），进出文件夹时列表按方向横移；收藏行共用同一套入场动效，于是两个面板看起来是一套东西
- 加载完成时进度条按弹簧向上缩回，下面的列表跟着平滑上移，不再硬跳；两端现在都是这样
- 浏览器端 lightbox 有了过渡：遮罩淡入、图片从略小推到正常，缩略图换成原图那一下是淡入变清晰而不是硬切。聊天页的 lightbox 也跟着受益，因为三个来源共用同一份实现。系统开启「减弱动态效果」后这三条动效全部关闭
- 浏览器端所有图标不再被读屏朗读。此前导航项会被念成「star 收藏」，因为图标字形是带内部标识符的生成内容
- 浏览器端导航用 `aria-current` 而不是 `aria-selected` 表示当前目的地。后者在 `<nav>` 里的裸 button 上会被读屏忽略，也就是说「当前在哪个目的地」从未被朗读过
- 单色档下，手机端的行首容器从 primary 色系改为 secondary 色系——浏览器端本来用的就是后者。现在两端只有一个 token
- 「允许电脑浏览手机存储」改用普通文件夹图标（不再是带人形的 `folder_shared`），「显示隐藏文件」用 Folder Eye
- Kotlin 源码里六份各写一遍的字节格式化实现收敛为一份

### 修复

- 设置页可展开行收起时会在原处留下一道双倍间隙，而弹簧回弹又让这一行进场时抖一下
- 上方的行正在收起时，分段控件的索引会跟着错位
- 嵌套的 Scaffold 重复施加了 window insets，导航栏被垫了两次
- 浏览器端的 `hidden` 并没有真的隐藏：作者样式里的 `display` 规则压过浏览器自带的 `[hidden]` 规则，于是这样隐藏的元素照样被画出来。这是个全局缺陷，也按全局修掉了
- 勾选收藏项会重绘整份收藏列表
- 本版新增代码（存储浏览、排序与搜索、缩略图与预览）在开发期间另有 31 个缺陷被发现并修掉，没有任何已发布版本带过它们

## [v1.19.0](https://github.com/Lifky/Flikky/releases/tag/v1.19.0) · 2026-08-26

### 新增
- 浏览器端整体重做为 Material 3 Expressive：导航柱 / 会话栏 / 功能栏三段并排，中间的手柄可拖拽改变两栏比例（也支持键盘），比例与折叠状态刷新后保持；窗口变窄自动换成底部导航条。登录页与导出页同样重做
- 浏览器端收藏面板：搜索、分类筛选、多选后批量保存。只读——增删改仍在手机端
- 浏览器端设置面板：布局偏好（导航柱靠右、两栏对调、重置分栏比例）、来自手机的只读项（语言 / 主题 / 会话时间戳）、以及显示版本号的「关于」
- 会话中的快捷设置补齐为**全部双端同步项**：语言、主题色、深色模式、AMOLED、设备名、两端头像、气泡圆角、头像显示、会话背景、会话时间戳、消息操作样式、消息撤回、允许撤回对端消息、收藏功能。会话运行时设置页是锁着的，缺哪一项就等于整场会话都调不了那一项
- 浏览器端跟随手机的 AMOLED 纯黑开关
- 已结束会话的行内操作补齐，单条会话不必再进多选

### 变更
- 默认主题色改为安安蓝
- 浏览器端改为「默认不可选中，内容显式可选」：消息文本、文件名、收藏条目、版本号可以正常划选复制；界面文字与图标不再被误选
- 图标字形改由 CSS 生成，不再是页面文本 —— 手机浏览器长按不会再选出 `arrow_upward` 这类图标内部名称，复制整条消息也不会带出图标名
- 滚动条改为仅在滚动时浮现，不再常驻占位
- 收藏分类筛选改用 mdui 官方 chip 组件
- 登录与导出页的按钮去掉按下形变，只保留明暗反馈

### 修复
- **双端同步：修复设置改回默认值方向不生效的问题。** 会话时间戳关不掉、消息操作样式切不回「常驻按钮」、允许撤回对端消息重新开启无效、收藏功能关不掉 —— 此前都只能手动刷新浏览器页面。推送给浏览器的数据里，取默认值的字段会被整个省略，浏览器把「字段缺席」读作「没有变化」；现在字段一律齐发
- 手机端在传输与导出之间切换后，浏览器停在旧地址刷新会陷入无限重连（或拿到 404），现在自动跳到正确的页面
- 浏览器与 App 两端长按图标都会选中并复制出图标名称
- 浏览器自己发出的文件被错误计入「打包为 ZIP」的保存范围
- 深色模式下 logo 不适配；某次修改后 logo 直接不显示
- 一键保存悬浮按钮与输入框不等高，且显隐时输入框宽度突跳
- 快捷设置「会话行为」区末行的底部圆角与首行顶部圆角不对称
- 分组对话框与浏览器端若干标签的文案

## [v1.18.0](https://github.com/Lifky/Flikky/releases/tag/v1.18.0) · 2026-08-15

### 新增
- 双端会话时间戳分隔条（默认关闭）：居中 pill 按 `yy/MM/dd HH:mm` 显示，首条消息前恒有一条，此后新消息距上一次已显示分隔条满 5 分钟再出现一条。App 设置是唯一开关，浏览器即时跟随，已渲染的历史消息同样即时生效

## [v1.0](https://github.com/Lifky/Flikky/tree/v1.0) · 2026-04-18

首个版本，Android 手机与浏览器之间的局域网互传闭环：

- Ktor（CIO）内嵌服务器：只绑定 Wi-Fi IPv4，绝不监听 `0.0.0.0`；CSP 等安全 header 附加到所有响应
- 一次性 6 位 PIN 认证：成功即作废，错误锁定/停服；token 走 HTTP-Only Cookie
- 文本与文件双向传输（multipart 上传 / 分块下载），WebSocket 实时消息与 1Hz 状态广播（时长/文件数/速率）
- 浏览器端：mdui（MD3 Web Components）离线打包约 380KB，分段 PIN 输入登录页 + 聊天页
- 前台服务（dataSync）与通知；锁屏隐藏 PIN，引导进 App 查看
- 手机端可通过 FileProvider 打开浏览器上传的文件
