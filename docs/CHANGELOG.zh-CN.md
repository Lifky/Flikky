# 更新日志

[English](./CHANGELOG.md) · **简体中文**

本文件记录 Flikky 每个版本面向用户的变更，格式参照 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)。版本号遵循 `x.y.z`：x 重大架构变更、y 功能新增、z Bug 修复。日期为 tag 创建日期。

## [v1.19.0](https://github.com/Lifky/Flikky/releases/tag/v1.19.0) · 2026-08-26

### 新增
- 浏览器端整体重做为 Material 3 Expressive：导航柱 / 会话栏 / 功能栏三段并排，中间的手柄可拖拽改变两栏比例（也支持键盘），比例与折叠状态刷新后保持；窗口变窄自动换成底部导航条。登录页与导出页同样重做
- 浏览器端收藏面板：搜索、分类筛选、多选后批量保存。只读——增删改仍在手机端
- 浏览器端设置面板：布局偏好（导航柱靠右、两栏对调、重置分栏比例）、来自手机的只读项（语言 / 主题 / 会话时间戳）、以及显示版本号的「关于」
- 会话中的快捷设置补齐为**全部双端同步项**：语言、主题色、深色模式、AMOLED、设备名、两端头像、气泡圆角、头像显示、会话背景、会话时间戳、消息操作样式、消息撤回、允许撤回对端消息、收藏功能。会话运行时设置页是锁着的，缺哪一项就等于整场会话都调不了那一项
- 浏览器端跟随手机的 AMOLED 纯黑开关
- 已结束会话的行内操作补齐，单条会话不必再进多选

### 变更
- 默认主题色改为安安蓝
- 浏览器端改为「默认不可选中，内容显式可选」：消息文本、文件名、收藏条目、版本号可以正常划选复制；界面文字与图标不再被误选
- 图标字形改由 CSS 生成，不再是页面文本 —— 手机浏览器长按不会再选出 `arrow_upward` 这类图标内部名称，复制整条消息也不会带出图标名
- 滚动条改为仅在滚动时浮现，不再常驻占位
- 收藏分类筛选改用 mdui 官方 chip 组件
- 登录与导出页的按钮去掉按下形变，只保留明暗反馈

### 修复
- **双端同步：修复设置改回默认值方向不生效的问题。** 会话时间戳关不掉、消息操作样式切不回「常驻按钮」、允许撤回对端消息重新开启无效、收藏功能关不掉 —— 此前都只能手动刷新浏览器页面。推送给浏览器的数据里，取默认值的字段会被整个省略，浏览器把「字段缺席」读作「没有变化」；现在字段一律齐发
- 手机端在传输与导出之间切换后，浏览器停在旧地址刷新会陷入无限重连（或拿到 404），现在自动跳到正确的页面
- 浏览器与 App 两端长按图标都会选中并复制出图标名称
- 浏览器自己发出的文件被错误计入「打包为 ZIP」的保存范围
- 深色模式下 logo 不适配；某次修改后 logo 直接不显示
- 一键保存悬浮按钮与输入框不等高，且显隐时输入框宽度突跳
- 快捷设置「会话行为」区末行的底部圆角与首行顶部圆角不对称
- 分组对话框与浏览器端若干标签的文案

## [v1.18.0](https://github.com/Lifky/Flikky/releases/tag/v1.18.0) · 2026-08-15

### 新增
- 双端会话时间戳分隔条（默认关闭）：居中 pill 按 `yy/MM/dd HH:mm` 显示，首条消息前恒有一条，此后新消息距上一次已显示分隔条满 5 分钟再出现一条。App 设置是唯一开关，浏览器即时跟随，已渲染的历史消息同样即时生效
- 会话中保持屏幕常亮（默认关闭）：服务运行中停留在会话页时屏幕不再熄灭；离开页面或停止服务即恢复系统默认熄屏
- 浏览器端一键保存：接收文件就绪达到 2 个后，消息区右下角出现悬浮按钮，提供「逐个保存 (N)」——按原始文件名依次下载全部文件——与「打包为 ZIP」——流式打包的纯文件归档，重名自动改名。ZIP 接口与其他文件路由走同一套会话鉴权

### 变更
- 两个新设置行配上官方 Material Symbols 图标，时间戳的说明移入信息对话框

### 修复
- 气泡圆角拖回默认值时，浏览器端不再回落到旧默认值；两端统一默认圆角为 10

## [v1.17.1](https://github.com/Lifky/Flikky/releases/tag/v1.17.1) · 2026-08-13

### 新增
- 收藏行内菜单：分享、移动到合集、用其他应用打开、保存到相册（仅图片视频）、另存为、删除。文本收藏另成一套——复制、移动到合集、删除，因为它没有落盘文件
- 收藏行尾部改为 split button：左半发送，右半展开上述菜单
- 收藏多选工具栏补齐批量操作（分享、保存到相册、另存为），与原有的移动、删除并列。每个文件类动作只作用于够得着的子集，并报告跳过了多少条
- 首页已结束会话的行内菜单：置顶、重命名、移动到分组、导出、删除——操作单条会话不必再长按进多选
- 没有可用 Wi-Fi 地址时拒绝开启传输，弹框说明同一 Wi-Fi 下的设备用浏览器即可连接，并提供直达 Wi-Fi 设置的按钮

### 变更
- 收藏行交互对齐文件总览：点图片进应用内预览，点其他文件交外部应用，点文本收藏复制，点 leading 进多选
- 非媒体文件行的分类图标放进 40dp 的 Material Expressive 异形容器，与缩略图占同一位置，所有标题起点落在同一条竖线上；四处文件行共用同一份实现
- 文本收藏同样占这一格，用引号图标，收藏页与快速发送 Sheet 一致
- 收藏页统一称容器为「合集」；共享的分组 chip、移动 Sheet 与管理框改由调用方决定用词
- 音频文件改用官方 audio_file 图标
- 选中行的 leading 容器改为浅色，不再是实心主色

### 修复
- 媒体缩略图与分类图标不再宽度不一，标题不会再在行与行之间左右跳动
- 收藏标题换行成两行时，leading 保持垂直居中
- 快速发送 Sheet 里的文本收藏完全没有 leading，导致标题缩进与文件行不同
- 缩略图解码失败时回落为图标容器，不再把 24dp 矢量图拉伸到 40dp
- 未连 Wi-Fi 就开启传输，不再留下空 URL、空 PIN、运行时长还在增长的假运行页面（服务其实已经自行退出）
- 收藏行的 split button 整体变小，菜单半边比发送半边窄，不再两半等宽

## [v1.17.0](https://github.com/Lifky/Flikky/releases/tag/v1.17.0) · 2026-08-10

### 新增
- 双端气泡媒体缩略图：图片与视频在气泡内按等比缩放展示缩略图；点按后 Android 端进入应用内图片预览，浏览器端进入全屏 lightbox。收藏页文件行同样显示缩略图
- 浏览器端消息操作跟随 App 的「消息操作样式」设置：常驻内联操作栏，或悬浮 hover 工具栏 + 右键 / 长按菜单；悬浮样式下整个气泡即下载入口
- 「允许撤回对端消息」设置：开启后任一端都可以撤回另一端的消息，由服务端在双端统一校验
- 文件总览操作动线重构：点按整行打开或预览、点按缩略图进入多选、每行溢出菜单，以及收藏 / 分享 / 存相册 / 另存为 / 删除的批量工具栏
- 检查更新：设置 > 关于中新增手动检查入口，并提供可选的启动时自动检查（默认关闭）。检查只访问 GitHub releases API，不携带任何设备或账号数据
- 浏览器端头像：设置中头像入口改为 App / 浏览器双 tab；浏览器头像保存在手机端，浏览器连接时自动下发
- 自定义主题色：在交互式对话框中任选 seed 色（饱和度/明度色板、色相滑条、双向同步的 Hex 输入），本地生成完整 Material 3 亮色/暗色/对比度色板并同步到浏览器
- 会话中的快捷发送面板可选择全部已存文件，不再局限于收藏
- 支持分享单个选中的收藏文件；设置中新增「删除全部数据」操作

### 改进
- 新安装默认值调整：气泡圆角 10、消息撤回开启、允许撤回对端消息开启、内联消息操作、「允许会话中返回」开启——已有的显式选择不会被覆盖
- 浏览器断连状态改为背景模糊、不可关闭的对话框；连接水印固定在消息视口中央，不再随消息滚动
- 多选顶栏改为「全选 / 取消全选」图标双态切换
- SVG 文件双端统一归为「其他」类：不提供预览、lightbox、缩略图与存相册（Android 系统不将 SVG 视为媒体）
- 双端文件气泡按类别显示图标（图片/视频/音频/文档/其他），与文件总览列表一致
- 设置项的长说明移入信息对话框；操作图标与语义对齐（预览统一用 visibility 图标）

### 修复
- 键盘弹出或收起时消息列表保持锚定，不再跳动
- 媒体气泡按真实媒体尺寸确定大小；浏览器端媒体气泡无边框，宽度唯一由图片决定
- 浏览器多文件上传逐个独立处理，单个失败不再中断其余文件
- 无扩展名的已存文件可以正确解码视频缩略图
- 关闭收藏功能后，文件总览中不再出现收藏入口
- 「检查更新」行在检查期间保持行高稳定
- 浏览器文件气泡在传输过程中即显示图标；手机向浏览器传文件完成后操作按钮恢复正常
- 从设置导入归档时，与其他导入一样走冲突决策流程

## [v1.0](https://github.com/Lifky/Flikky/tree/v1.0) · 2026-04-18

首个版本，Android 手机与浏览器之间的局域网互传闭环：

- Ktor（CIO）内嵌服务器：只绑定 Wi-Fi IPv4，绝不监听 `0.0.0.0`；CSP 等安全 header 附加到所有响应
- 一次性 6 位 PIN 认证：成功即作废，错误锁定/停服；token 走 HTTP-Only Cookie
- 文本与文件双向传输（multipart 上传 / 分块下载），WebSocket 实时消息与 1Hz 状态广播（时长/文件数/速率）
- 浏览器端：mdui（MD3 Web Components）离线打包约 380KB，分段 PIN 输入登录页 + 聊天页
- 前台服务（dataSync）与通知；锁屏隐藏 PIN，引导进 App 查看
- 手机端可通过 FileProvider 打开浏览器上传的文件
